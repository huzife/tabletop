# 游戏设计总览

本目录存放各个具体游戏的规则、房间设置、状态机、AI、浏览器交互和测试边界。它们是游戏插件的领域设计文档，不属于平台级架构、协议或数据模型的定义范围。

平台通用能力及新游戏接入方式见[项目根目录的文档索引](../../README.md#文档索引)、[总体架构设计](../architecture.md)和[游戏插件扩展指南](../game-plugin-guide.md)。新增游戏时，应在本目录增加独立文档，并在本页登记；不要把具体规则写入平台级文档。

## 首期游戏

- [五子棋规则与实现设计](gomoku.md)：15x15 五子棋的规则预设、禁手、计时、协商操作与 AI 设计。
- [飞行棋规则与实现设计](ludo.md)：四色十字飞行棋的路径拓扑、骰子、叠机、跳跃、飞行、排名与 AI 设计。
- [台球规则与实现设计](billiards.md)：中式八球与斯诺克的标准桌台、规则状态机、旋转物理和 Canvas 交互设计。

## 新游戏文档约定

每个新游戏至少应提供一份独立 Markdown 文档，清楚说明以下内容：

- 游戏目标、人数范围、房间设置和开局条件。
- 棋盘或牌桌的逻辑模型、权威状态和动作定义。
- 完整的回合、胜负、超时、断线接管及 AI 规则。
- 浏览器需要呈现的交互状态，以及规则测试的关键场景。
- 对应插件的实现目录和平台接口边界。

游戏规则发生变化时，应同时更新对应游戏文档和测试。平台通用协议、认证、房间生命周期、连接恢复等能力发生变化时，则更新 `docs/` 下相应的平台级文档。
